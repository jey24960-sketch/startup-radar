# StartupRadar 2.0 운영 안내

GFC 회원용 창업 지원 공고 서비스다. 공식 출처에서 공고를 수집하고, 확인 가능한 지원 조건을 팀 프로필과 비교해 추천한다. 최종 신청 자격과 선정 여부는 주관기관이 결정한다.

## 구성

- 웹: 기존 GFC React/Vercel의 `/notice`, `/notice/radar/{program_id}`, `/radar/settings`, `/radar/admin`.
- 인증: 기존 GFC Supabase 세션. 로그인 외에 GFC 회원 여부와 해당 팀의 소유·편집·조회 권한을 확인한다. 익명과 비회원은 Radar 데이터를 읽을 수 없다.
- 저장: 기존 공유 프로젝트 `etvffzxqdgblvkfdikwl`의 `startup_radar` 스키마. 수동 공지는 별도 `public.gfc_notices`다.
- 실행: GitHub Actions의 Python 배치. 공고·첨부·출처·버전·판정·추천·알림 이력을 DB에 저장한다. 상시 Python 웹 서버는 필요하지 않다.
- 판정: 출처로 검증된 조건에 결정 규칙을 적용한다. AI는 근거를 추출하며, 규칙에 의한 자격 미충족을 뒤집지 못한다. 불명확한 정보는 미확인으로 남긴다.
- 프로필 저장: RPC가 버전을 올리고 계산 요청을 등록한다. 배치가 계산을 완료하기 전에는 이전 점수를 현재 점수로 표시하지 않는다.

## 수집 범위와 실행 일정

운영 DB 설정이 기준이다. `sources.json`을 전체 재등록하면 검증된 설정을 덮어쓸 수 있으므로 사용하지 않는다.

K-Startup은 최신 20건과 현재 모집 중인 주요 공고군 세 개(모두의 창업 프로젝트, SVC Seoul, 베트남 테크페스트)를 공식 API에서 조회한다. 조회별 최대 한 페이지이며 발행기관 공고 ID로 중복을 제거한다. 기업마당은 최신 20건·한 페이지다. 이는 제한된 현재 공고 범위이며 전국·과거 공고 전수 수집이 아니다. 대학 출처는 수집 자료를 보존하되 불완전한 자동 경로를 운영 필수 출처로 간주하지 않는다.

GitHub cron은 `17 * * * *`(UTC)이다. 매시간 17분에 TICK이 실행되며 DB의 서울 시간 일정과 날짜별 실행 기록으로 중복을 제한한다.

- 수집: 매일 06:17 KST부터 하루 한 번.
- 주간 요약: 화요일 15:17 KST부터 주당 한 번.
- D-7·D-3 마감 알림: 매일 15:17 KST부터 하루 한 번.
- 중요 신규 공고 알림: 일일 수집 후 최신 자격·선호·중복 여부를 다시 확인한다.
- 프로필 계산: 매시간 TICK에서 처리하므로 저장 즉시 결과가 나오는 방식은 아니다.

GitHub 일정은 지연될 수 있다. 정확한 분 단위 도착이나 24시간 내내 실행되는 서버를 보장하지 않는다.

## 안전한 부분 성공

모든 발견 공고가 저장됐지만 페이지 제한, 첨부 파싱, 근거 부족 경고가 있으면 배치는 경고를 동반한 성공으로 종료할 수 있다. 원본 수집 실행과 출처 상태의 PARTIAL 기록은 그대로 남는다. 실제 접근·저장 실패 및 AI 인증·권한 실패는 성공으로 바꾸지 않는다.

본문이 없는 K-Startup 공고는 공식 API 사실만 저장하고 자격 판정은 미검증 상태로 둔다. 손상 문자를 포함한 PDF는 문자를 지우거나 조건을 이어 붙이지 않고 문서 분석 실패로 남긴다. 수작업 검토는 원본 파일 해시·본문·API가 일치할 때만 재사용하며, 다른 공고 버전에 참여 답변을 자동 전이하지 않는다.

미검증 근거는 확신 있는 지원 가능 판정이나 높은 확신의 알림으로 승격하지 않는다. 자료 품질 분류는 신청 마감 여부 및 사용자의 자격 판정과 별개다. ‘지원 가능’도 정원·선정·실제 참여를 보장하지 않는다.

## 알림과 장애 복구

채널 구독과 팀 설정이 모두 허용해야 발송한다. 구독자가 0명이면 새 구독자를 만들지 않고 0건으로 끝난다. 실패와 전달 여부 불명을 구분하며, 전달 여부가 불명인 알림을 자동 재발송하지 않는다. Telegram과 PostgreSQL 사이에 완전한 단일 트랜잭션은 없으므로 엄밀한 외부 전달 exactly-once 보장은 하지 않는다.

GitHub 동시 실행 제어와 DB의 지속 실행 소유 기록이 중복 작업을 제한한다. 실행이 끊겨도 시간이 지났다는 이유만으로 잠금을 빼앗지 않는다. `execution-status`로 실행 ID와 GitHub run ID를 확인하고, 실제 종료를 확인한 경우에만 `recover-execution --confirm-stopped`로 복구한다. 중단된 수집 기록과 부분 저장 결과도 함께 확인한다. 자세한 명령은 `python -m radar.cli --help`와 기존 OPERATIONS 문서를 참고한다.

운영 Secrets는 `RADAR_DATABASE_URL`, `ANTHROPIC_API_KEY`, `KSTARTUP_API_KEY`, `BIZINFO_API_KEY`, `TELEGRAM_BOT_TOKEN`이다. Python에는 DB 주소가 `DATABASE_URL`로 전달된다. GitHub에 대기 등록된 작업은 이후 교체한 Secret이 반영되지 않을 수 있으므로 인증 문제 수정 후에는 기존 작업의 종료를 확인하고 새 실행을 만든다. 비밀값은 브라우저·문서·로그에 넣지 않는다.

## 중단 및 V1 복귀

V2를 멈추려면 저장소 변수 `RADAR_V2_ENABLED`와 `RADAR_V2_DELIVERY_ENABLED`를 false로, DB scheduling의 enabled와 ingestion_enabled를 false로 설정한다. 실행 중 작업은 종료 여부와 부분 효과를 확인한다. DB나 수집 이력을 삭제할 필요가 없다.

V1 코드와 워크플로는 보존한다. V1 일정은 `disabled_manually`이며 `.startup_radar_auto_run`도 false다. 필요할 때만 V2를 중단한 후 V1을 명시적으로 다시 활성화한다. V1의 보존 일정은 화·금 15:00 KST(`0 6 * * 2,5` UTC)다. V1과 V2를 동시에 자동 발송하지 않는다.
