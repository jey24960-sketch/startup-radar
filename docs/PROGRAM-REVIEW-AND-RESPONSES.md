# 원문 검토와 공고별 참여 답변

이미지의 OCR 초안은 자격 근거로 자동 승인하지 않는다. 운영자는 `tools.program_review export`로 현재 공고 버전의 자료를 내보내고, 원본의 모든 페이지와 발행기관의 대체 텍스트를 대조한 결정 파일을 `apply`에 전달한다. 에이전트의 시각 검토는 `AGENT_VISUAL_REVIEW`, 운영자의 검토는 `OPERATOR_REVIEW`로 구별한다. 이 기록이 사람의 법적 확인이나 기관의 자격 승인을 뜻하지 않는다.

검토 결정은 원문 본문·메타데이터·첨부파일 해시에 묶인다. 다운로드 실패는 승인할 수 없으며, 읽지 못한 문서는 페이지별 대조와 누락 범위 설명이 필요하다. 필수 조건은 원문에 있는 인용문으로 검증한다. 원래 문서의 파싱 실패는 그대로 남기고, 별도 대조 기록을 보여준다. 검토 후 원본이 바뀌면 기존 결정을 재사용하지 않는다. 추가 HTTPS 문서는 다시 가져와 바이트 해시와 텍스트를 확인하므로 동적인 HTML은 내용이 같아도 재검토가 필요할 수 있다. 여러 수집 출처가 합쳐진 공고는 현재 명시적 출처 선택 기능이 없어 이 검토 경로에서 거절한다.

검토 결과와 재사용 기록은 하나의 DB 트랜잭션에 저장한다. 현재 버전 비교와 기존 durable worker 실행 소유권을 사용한다. `revoke`는 검토 결정을 철회하고 해당 결정이 현재 근거인 경우 새 미확인 버전을 만든다. 이전 공고와 감사 기록은 보존한다. apply/revoke 이후 `REFRESH`가 필요하며 Telegram 발송은 하지 않는다.

참여 약속은 팀의 일반 속성이 아니다. `program_response` 조건의 안정적인 질문 ID와 예/아니요 기대값을 공고 버전에 저장하고, 팀의 답변은 `team_program_responses`에 별도로 저장한다. 미확인과 아니요를 구별한다. 일반 AI 추출은 이 질문을 확정할 수 없고, 원문 검토가 필요하다.

GFC 화면은 검증된 질문만 표시한다. Stage 0 프리셋에서는 최소 프로필 생성 후 답할 수 있다. 실제 답변을 모르면 미확인으로 남긴다. OWNER/EDITOR만 현재 공고 버전에 답하며, 다른 팀·비회원·읽기 전용 회원의 쓰기를 거부한다. 답변은 공고 버전을 넘겨 자동 승계하지 않는다. 삭제는 해당 답변을 미확인으로 되돌린다.

`gfc_radar_program_responses`는 기존 Supabase JWT를 사용하는 추가 RPC다. public 함수는 invoker이며, private definer가 명시적으로 회원·팀 권한을 검사하고 답변, 감사 기록, 계산 요청을 함께 저장한다. CAS revision으로 충돌을 검출하고 같은 답변 재전송은 중복 처리한다. 익명 호출과 직접 클라이언트 쓰기는 허용하지 않는다. 검토 결정 테이블은 worker 전용이다.

Python API 상태는 **A. NOT REQUIRED**다. 기존 9개 회원 경로에 답변 저장 RPC 1개가 추가됐으며, Python은 배치 계산만 담당한다. 결과 캐시는 팀 프로필뿐 아니라 해당 버전의 답변 스냅샷도 비교한다. 계산 중 새 답변이 들어오면 기존 결과는 숨기고 재계산 대기로 남긴다. 스케줄이 꺼진 검증 환경에서는 운영자의 REFRESH 실행까지 대기가 지속된다.

필수 조건 불충족은 INELIGIBLE, 참여 답변 미확인은 NEEDS_INFO, 필수 자료 미확인은 UNVERIFIABLE로 유지한다. 모든 필수 조건을 확인해야 ELIGIBLE이다. 지원 가능은 선정·잔여 정원·지원금 지급을 보장하지 않는다. 지원금의 조건과 일정 충돌은 material_notes로 별도 표시한다.

공유 DB 변경은 추가 private 테이블 2개, 결과의 답변 스냅샷 열, 답변 RPC와 기존 DTO 함수 확장이다. GFC의 기존 public 데이터 테이블과 Auth 역할은 변경하지 않는다. DB migration과 새 worker 코드를 함께 준비한 뒤 program_response 공고를 저장해야 한다. 이전 worker는 새 조건을 해석할 수 없다. 운영 스케줄·main 병합·V1 종료는 별도 운영 수용 기준과 승인 이후다.
